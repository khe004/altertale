## Sabre

检查了 `readme.md`、`Main.java`、`Session.java`、`Problem.java`、动作/认知/条件类型以及解析器。上游模型包含实体、属性、初始状态、动作、触发器、角色认知和作者/角色效用。

它搜索已定义动作组成的计划，并要求动作对执行角色具有动机上的解释。它不负责创造新行动类型、从小说验证因果条件，也不提供战争概率模拟。

实际环境是 OpenJDK 21 的运行时，没有 `javac`；因此没有完成从源码编译。上游自带 `build/jar/sabre.jar` 可以直接执行。用 AlterTale JSON 模型导出两个授权北伐后的状态（包含该轮的侦察和魏方增援），结果为：

```text
baseline: raid_jingzhou()
zhuge: coordinate_with_wei()
```

这说明同一行动库可以支持不同部署下的下一步规划，尚不能证明完整战役模型的性能或正确性。

AlterTale 的导出器只导出一个 NPC 的行动及效用，以便和本地单角色规划比较。布尔状态编码为 0/1 数值，未知信息编码为 `?`；实际世界与角色认知分别写入。导出器保留侦察的信息获取效果，不导出玩家命令、强制结局触发器或完整多人解释搜索。本地 Python 的候选比较追求限定深度内最大效用改善；Sabre 返回达到作者效用目标的计划，两者不保证普遍相同。

运行方法（先将固定版本 Sabre 单独检出到自己的参考目录）：

```bash
python -m altertale compare --sabre-jar /path/to/sabre/build/jar/sabre.jar
```

许可证：上游 GPL-3.0。当前只提供独立编写的文本导出器和调用外部 JAR 的实验入口，不发布上游代码或二进制。正式依赖、链接或分发的方式仍需在采用时评估。

## StoryWorld Engine

主要检查 `backend/app/storyworld/engine.py`、`models.py`、`llm.py` 和 `backend/tests/test_storyworld_engine.py`。

有价值的机制包括：分支使用深拷贝、检查点包含当前分支完整状态、回放有固定事件 ID、数据模型禁止额外字段。上游的四个核心测试验证了预算、分支隔离、确定性、断点续跑和预览流程。

但目前的限制直接影响荆州需求：

- 三个共同回合、三条分支、每条三个回合，不只是默认配置，数据模型也限制了该形状。
- 角色数量限制为 6～8 个。
- `_decisions()` 生成三种固定形式的文本决策：揭露秘密、隐藏秘密结盟、保护对手；不是从可行战略行动中计算选项。
- `_step()` 将模型结果追加成世界事实字符串，更新张力和关系分数，没有声明式兵力、补给、地区控制权转换规则。
- 原文 `source_text` 只把前 4000 字符加入事实；上传长文本不等于完成全书结构抽取。
- 因果链接主要指向前一个事件，不能直接视为经过验证的领域因果关系。

实际以刘备、关羽、诸葛亮、孙权、吕蒙、曹操六人分别运行两种部署的 mock 模式，均完成 12 回合；变化路径仅包括 `world.facts`、`world.tension` 和人物关系。这个检查验证了接口可运行，也说明兵力和地区控制模型需要另外实现。真实 LLM 模式、数据库和完整 API 测试未在本次评估中运行。

许可证：AGPL-3.0。本阶段只借鉴机制，没有导入该项目的实现。

## There and Back Again

检查了 `decompose.py`、`fix_decompose.py`、`compose.py`、`glaive.py`、`utils.py` 以及领域提取提示。

它展示了自然语言 → Glaive PDDL 领域与问题 → 规划 → 自然语言故事的流程，并保存了研究结果。适合参考如何要求输出前置条件、效果、角色意图，以及如何根据编译错误修正模型。

工程限制包括：

- `utils.py` 使用旧式 `openai.ChatCompletion.create`；与当前 OpenAI Python SDK 的接口需要适配。
- Glaive 使用固定临时文件路径，直接作为多人/多分支服务会发生共享文件冲突。
- Glaive 的 PDDL 不能直接作为 Sabre 领域文件，仍需要模型转换。
- 现成实验针对短故事；本次没有验证长篇小说抽取。

README 指定 Java 7，但附带 Glaive JAR 的 Ark 示例实际在 OpenJDK 21 上成功规划（39 个节点被访问、176 个生成）。这只证明该示例的兼容性。没有配置语言模型 API 凭据，因此未执行收费的抽取与重写步骤。

所检出的顶层未发现项目级 LICENSE；附带规划器的授权应单独核实。本阶段没有复制提示词、源代码、研究故事或规划器二进制。

## 第一阶段实现选择

采用 Python 标准库实现可运行的局部模型，理由是当前最大的待验证项是行动库、来源和状态转换，使用外部服务不会消除这些建模工作。

- 声明式 JSON 是规则和参数的单一数据源。
- 世界状态与各 NPC 的认知分别保存。
- 本地规划器只搜索同一 NPC 的最多两步计划，执行其中第一步，下一轮重新规划。
- 世界规则检查实际条件后提交效果，资源守恒和状态约束由规则层负责。
- 同一份模型可导出给 Sabre 进行下一步动作验证。

这是一套实验运行器，不是完整叙事规划引擎。下一阶段应重点评估 Sabre 的动态状态接入、完整多角色计划、时间与战争不确定性，以及角色拒绝命令的处理，再决定替换哪一部分。
