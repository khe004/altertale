> 状态：已实现第一版（2026-11）。待定四项按建议定下：允许越过底线（提示一次，后果照推）；两个开局都做；身在曹营一段在"屯土山"开局里压成两回，"得信"开局直接略过；世界图谱先在蜀汉线做，千里走单骑同样可用。回目、日期按毛宗岗本，标"待核"的地方要对照原文。

## 目的

现在的推演是为战争调校的：玩家是主公，在后方下令，命令按驿程送到，前方将帅自己决断，状态以兵马、城池为主。这个试点要验证另一种尺度：**玩家就是主角本人，亲自在场行动**。

选关羽千里走单骑，原因：

- 人物卡、演义设定、原著事件池的写法都能复用，只验证新机制，不同时换题材。
- 这一段几乎没有兵马，靠的是个人抉择（恩义两难）、身份冲突（身在曹营）和信息（何时知道兄长下落、守关将知不知道曹操放行）。
- 消息传播正好是剧情的核心：曹操的放行文书追不上关羽，五关守将各凭所知行事；关羽斩颜良、文丑，又把身在袁营的刘备置于险地。驿程表照样能用，只是从"命令在途"换成了"消息在途"。

跑通之后，再把通用内核和"人物剧本包"的边界定下来，以后接非三国的小说。

## 和战争包的不同

| | 战争包（蜀汉线） | 人物剧本包（本试点） |
| --- | --- | --- |
| 玩家位置 | 坐镇后方 | 随主角移动，主角在哪里，玩家就在哪里 |
| 玩家输入 | 下令、定方略与授权 | 亲自行动：说什么、做什么、去哪里 |
| 一回的跨度 | 2～4 个月 | 一场戏，半日到一月不等；赶路可以快进，对峙逐句推 |
| 状态主体 | 兵马、城池、大势 | 主角处境、随行、随身之物、人情、所知 |
| 在途的东西 | 军令 | 消息：书信、文书、传闻、目击 |
| 驱动力 | 几股持续的大势（曹操争汉中…） | 配角各自的打算和时间表 |
| 选项来源 | 谋士进言 | 随行与身边人的进言（孙乾、二嫂、张辽、胡班……），加上主角自己的念头 |
| 评分 | 地盘、兵马、民心、大势 | 兄弟重聚、二嫂安危、义名、恩怨、时机、收获 |

### 状态字段

沿用 `figures`、`events`、`intel`、`canon`；去掉 `forces`、`places`、`in_transit` 的军令含义，改为下面这些：

- **`self`**：主角的处境。`where`、`date`、`wounds`（伤，如"左臂箭伤，未愈"）、`mount`（赤兔）、`arms`、`title`（汉寿亭侯印：在身、已挂）、`pass`（通行文凭：无、有，谁签发）。
- **`retinue`**：随行。二嫂、车仗、从人，以及后来加入的人（廖化、周仓、关平），各带状态。二嫂失陷是败局线之一。
- **`goods`**：随身之物与财物，如曹操所赠金银、锦袍、胡华的书信。封金就是把赠金留下。物品可以解锁行动（有胡华的书信，才能取信胡班），但只解锁"能做"，不保证成功。
- **`bonds`**：人情账，写成具体的事，不写好感数值。例：`{ with: "曹操", what: "厚待之恩，未报", since: "第二十五回" }`、`{ with: "张辽", what: "土山说降，约三事的见证" }`、`{ with: "张飞", what: "疑关羽降曹", since: "下邳失守后" }`。人物按这些行事；每条变化都留着来路（"斩颜良，报了曹恩"），不悄悄改写。
- **`vows`**：誓约。约三事的第三条"但知皇叔去向，不管千里万里，便当辞去"；"立功报曹，然后去"。违背誓约本身不被禁止，但会记进义名、影响人情。
- **`facts`**（知情账）：见下一节。
- **`clocks`**：配角的打算和时间表，代替驱动力。例：袁曹在官渡一线的战局（原著时间推进）；刘备的去向（袁绍营中 → 汝南）；张飞在古城；曹操对关羽的打算（厚待留人 → 放行 → 补发文书）；夏侯惇的态度。

### 知情账：这次最要紧的机制

战争包里玩家是主公，大半局面看得到；主角视角下，幕后的事本来就不该知道。入书纪的示例就在这上面出了错：玩家从没听说过"执法堂偏院深夜亮灯"，却能选"（局已布下）斗心"去当众质问。

做法：

- 每条要紧的事实记成 `{ id, what, knownBy: [{ who, how, when }] }`，`how` 是目击、亲历、听某人说、看到书信、传闻。传闻可以是错的：事实本身和某人以为的样子分开记。
- 消息要靠人或书信传过去，按驿程走。例：关羽在白马斩颜良，消息几天后传到袁绍营中，刘备的危险是从这时开始，不是从斩颜良那一刻开始；曹操补发的放行文书，几天后才能追上关羽，在那之前到达的关口，守将并不知道曹操已经放行。
- **复核（代码查）**：
  1. 选项和推演出的主角言行，只能引用主角已知的事。引用了未知的事，打回重推。
  2. 配角的行动只能依据该配角已知的事（沿用现有规则）。
  3. 主角不在场的事件默认 `known: false`，传到了才转为已知，并且要写明是怎么传到的。
  4. 消息传递的速度不能快过驿程（复用 `travelDays`）。

### 行动与可行性判定

玩家可以选选项，也可以亲手写行动（说什么、做什么）。手写的行动先过一道判定，复用现在拆令和预检的位置：

- **能不能做**：在不在场、能力够不够（复用人物卡的 `martial`、`abilities`）、手上有没有需要的东西、知不知道需要知道的事。
- **合不合关羽的性子**：人物卡里的 `floor`（底线）。比如抛下二嫂独自走、投降袁绍、对刘备不义，关羽不会这么做。选项一律守底线；手写的行动越过底线时，提示一次"关羽不会这样做"，玩家坚持就照做（像现在的"仍然下达"），后果照推，义名和人情相应变化。是否允许越过底线，见文末"待定"。
- **结果由推演定**：判定只说做不做得到、有什么风险，成败由推演依据局面决定。

### 回的节奏与决断时刻

每回推进到下一个需要主角拿主意的时刻：

- 得到新消息（兄长下落、曹操的态度、关前有埋伏的风声）；
- 有人拦路、相求、相劝（守关将要文凭；廖化愿相随；张辽来劝）；
- 恩义两难（报曹恩还是即刻去；斩不斩拦路的人）；
- 计划败露或身陷险境（荥阳火计、镇国寺伏兵）。

赶路、宴饮、日常不算决断时刻，快进一笔带过，复用 `gapPoint` 的思路。一回的天数上限按段落设：身在曹营可以一回一月，过关时一回一两日。

### 双轨制照用

原著开局带原著节拍：一路照原著行事（选 ★），就照演义展开，只润色不改结果；第一个不同的行动起，转入自由推演。这一点和蜀汉线相同。

## 界面：借鉴入书纪

入书纪的示例里，状态面板和世界图谱做得好。它们和题材无关，蜀汉线也用得上，而且我们的数据（人物、事件、原著事件的状态、分支）比它全，可以做得更扎实。

### 状态面板

现在的"局势"面板是战争版：地图、大势、兵马、人物、在途军令、所知、暗线、纪事。人物剧本包改成：

- **主角**：身份、位置、日期、伤势、坐骑与兵器、印与文凭。入书纪的位置和时辰整局没变过（到决赛还写"外门弟子舍 · 大比前夜·戌时"），我们要每回从推演结果更新。
- **随行**：二嫂、从人、新加入的人，各带状态。
- **随身之物**：每样标明从哪来、能做什么（胡华的书信可以取信胡班）。
- **人情与誓约**：`bonds`、`vows`，每条都能点开看来路（哪一回、因为什么）。
- **所知**：保留，按知情账生成，标明消息来源（"孙乾面告""传闻"）。
- **本回变化**：入书纪每段后面有"【剑意+5，声望+10】"这样的结算，让玩家感到选择有分量。我们不用数值，改成列出本回状态的变化（"得赤兔马""曹恩已报""张飞闻知你斩颜良（传闻）"），由代码对比前后两回的状态生成，不另调模型。

### 世界图谱（新页面，或从面板进入）

分五个视图，都只用玩家已知的内容，并且都能追到出处：

1. **人物关系**：力导向图，节点是玩家已知的人物，边是 `bonds` 加人物卡里的 `relations`。点边看证据：原著关系注回目，本局形成的关系注"第几回、因为什么"。边带历史，比如张飞：结义兄弟 → 疑关羽降曹 → 释疑。入书纪的"剧情进度"滑块很好，我们直接按回数拖，看第几回时的关系网。
2. **势力格局**：按阵营列已知成员和他们此刻的位置、态度。蜀汉线可以把现在的兵马、城池放到这里。
3. **事件时间线**：两层对照。上层是原著事件池，每条标已发生、变形发生、失效、尚未到；下层是本局发生的事。入书纪的"我的世界线"在剧本模式下打完一局还是空的，我们的推演本来就逐回记事件，直接就能用。
4. **地图与路线**：主角走过的路线、关隘、守将（已知的才显示）、每个地点的通行条件（要不要文凭）。蜀汉线就是现在的形势图。
5. **我的世界线**：分支树。我们本来就支持回到任一回另作决断，这里把各分支画出来，标出和原著分开的那一回（`railOff`）。

**防剧透**：入书纪的人物卡默认把全书经历都写出来（主角卡直接写到终局），只能靠玩家自己拖滑块。我们默认只显示到当前回为止、玩家已知的内容，原著后文要玩家主动点开。

## 实现步骤

1. **定规格**（本文）：作者确认范围、机制和下面的待定项。
2. **拆出题材包接口**：把引擎里和战争相关的部分收进"战争包"，蜀汉线照常运行。初看可能涉及推演规则与格式（`simRules`、`simFormat`）、状态归一（`normalize`）、复核（`checkSim`）、评分（`scoreEnding`）和面板（`renderPanel`），要细看代码再定。验收：现有存档和 fixtures 照常可读，`tools/check.js` 通过。
3. **人物剧本包与千里走单骑数据**：新的状态字段、知情账与消息传递、可行性判定、本回变化；`web/data/eras/` 下新增这一段的配置和事件池；人物卡补孔秀、韩福、孟坦、卞喜、王植、胡班、秦琪、蔡阳、普净、廖化、周仓等。
4. **实测**：用 `tools/playtest.js` 跑几种打法：原著线（照 ★ 走）、早走（得信即走，不斩颜良）、当面辞成拿到文凭、径往河北。重点查知情账有没有漏（未卜先知）、消息有没有快过驿程、守将的行为与其所知是否相符。
5. **世界图谱**：先在蜀汉线上做（数据现成），再接到千里走单骑。
