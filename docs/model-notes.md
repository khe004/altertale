# 荆州模型说明

## 来源与假设

规则文件为 [`altertale/data/jingzhou.json`](../altertale/data/jingzhou.json)，版本 `0.1.0`。当前有 31 个状态字段和 15 个行动/触发器。

采用维基文库《三國演義》120 回本的章节转录作为工作文本，引用固定修订号：

- [第 73 回，修订 2568035](https://zh.wikisource.org/w/index.php?oldid=2568035)：刘备/诸葛亮在成都安排北伐、吴魏联系、王甫提醒后方风险、沿江烽火台等。
- [第 75 回，修订 2568039](https://zh.wikisource.org/w/index.php?oldid=2568039)：魏方增援，吕蒙/陆逊探查和利用撤防，袭取荆州。吴魏联络本来就在原著中，替代行动标签表示军事联动的落实。
- [第 77 回，修订 2568041](https://zh.wikisource.org/w/index.php?oldid=2568041)：接续关羽被俘后的情节，作为结果定位。demo 在被俘或撤回时结束，不模拟处决。

这是章节事件的局部抽象，未完成原著全线复现与校勘。默认三次玩家决策包含实验性的撤军令，不能将整条演示路径称作严格原著路线。

所有兵力、补给、时间、行动充分条件及人物目标权重均是人工模型假设。JSON 中每个行动引用来源或假设 ID，记录在 `provenance`。

## 反事实起点

`zhuge` 起点表示：北伐前诸葛亮已经完成调遣，并在荆州获得后方协同职责。与基线相比改变四项：

| 字段 | 基线 | 留守 |
| --- | --- | --- |
| 诸葛亮位置 | 益州 | 荆州 |
| 后方协同 | 0 | 2 |
| 刘备集团可用资源 | 6 | 4 |
| 益州参谋容量 | 3 | 2 |

调遣行程暂未模拟；益州参谋容量目前只记录机会成本，尚无益州事件消耗或检验它。这是模型尚未覆盖的影响。

## 决策与行动

玩家可以授权北伐、继续攻城、增援后方、加强戒备、提出停战、下令撤军。停战只是提议，吴方依据自身目标决定接受或采取其他行动。第一版假设关羽执行刘备撤军令；这项假设应在后续加入拒令、权限及执行风险时替换。

每次玩家命令后，吴方和魏方依次根据当前已知状态规划，最多各执行一个行动。两步搜索只包含自己的行动，不预测其他角色在这两步之间的反应，也不模拟概率或完整博弈。这一轮序本身就是可调整的模型假设。

吴方起初不知道后方兵力和协同，侦察后才能得到信息。兵力调动不会自动通知敌方。旧情报可能导致尝试一个已不可行的动作，规则层会阻止它，并记录阻塞条件及此次接触获得的信息。当前这种被阻止的尝试不扣除远征成本或时间，是第一版的简化。

游戏交互只展示刘备能观察到的事件和报告。批量对照与 JSON trace 是开发者视角，包含隐藏行动和各角色认知。

## 状态与因果

- 前线、后方、预备队及损失/失去控制的部队总数保持不变。
- 各资源不为负；人物位置使用单值，并校验进行中、撤回和被俘状态对应的位置。
- 先检查动作条件，再根据同一个旧状态计算全部效果，验证后一次提交。
- 每个事件保存检查结果、状态差异、信息更新、规划动机及来源标签。
- 因果链接指向最近改变该动作前置条件的事件，不只是上一个回合。
- 原著候选事件保存的是“当前是否满足局部条件”，不保证该事件以后永远有效或失效。

保存记录嵌入完整模型、模型校验值、初始状态、玩家决策、事件与最终认知。回放重新执行决策并比较整份记录；当前模型没有随机性，因此不需要随机种子。

## 对照结果

相同命令：授权北伐 → 继续攻城 → 下令撤军。

| 实验 | 吴方第二次行动 | 最后结果 |
| --- | --- | --- |
| 基线 | 袭取荆州 | 后方失守，关羽被俘 |
| 诸葛亮留守 | 落实吴魏军事联动 | 关羽撤回，荆州仍在刘备集团手中 |
| 留守，但敌方突破门槛从 3 改为 4 | 袭取荆州 | 留守路线仍然失败 |

袭击条件是 `后方兵力 + 协同 + 额外戒备 < 敌方突破门槛`。数值只是一个透明、可更换的假设。提高门槛代表敌方具备突破更强防备的能力。

选择“授权北伐 → 增援后方 → 撤军”也可以让基线路线保存荆州；结局由行动条件决定，没有按场景名称写死。

这验证了局部因果模型可运行、决策有影响、替代行动能衔接，以及结论对假设敏感。它没有验证历史真实性、半年完整叙事、全书抽取或无限剧情生成。
