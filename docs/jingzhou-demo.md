# 《异章：荆州》demo 规格

## 要验证的问题

当玩家改变原著的一项关键部署后，系统能否根据人物目标、认知和世界状态，生成连续、可解释的后续事件，并继续提供有影响的决策？

首个实验比较原著部署和“诸葛亮已提前留守荆州”两种起点。留守使哪些行动变得可行或不可行、吴魏如何响应、关羽是否撤军，都应由明确规则及决策产生。

当前实现与尚未覆盖的部分见 [模型说明](model-notes.md)，参考引擎检查见 [代码评估](engine-evaluation.md)。运行命令见 [项目说明](../README.md)。第一轮实验已经运行，尚未完成本规格中的完整半年范围。

## 第一版范围

- 故事基线：《三国演义》；建模前确定具体文本版本与章节范围。
- 时间窗口：关羽北伐前的局部状态至荆州危机结束，最多约半年；允许提前结束。
- 玩家角色：刘备。
- 势力：刘备集团、孙权集团、曹操集团。
- 核心人物候选：刘备、关羽、诸葛亮、孙权、吕蒙、曹操、曹仁，以及解释后方失守所必需的人物。
- 地点按决策需要聚合，至少覆盖益州、荆州后方和襄樊前线。
- 第一轮实验准备约 10～15 种行动模板，每条路线观察约 5～10 个重要事件；这些数量是范围控制目标。

人物和地点只在会影响行动条件、信息或结果时细分。玩家可以改变自己的命令，其他角色如何响应取决于各自目标、认知和执行条件。

## 最小数据模型

| 数据 | 需要记录的内容 |
| --- | --- |
| 世界状态 | 时间、人物位置与生死、地区控制权、兵力与补给等必要资源、外交状态 |
| 人物与势力 | 目标、优先级、可调动资源、权限及已知信息 |
| 行动模板 | 行动者、前置条件、资源代价、时间代价、效果、信息传播 |
| 原著事件 | 原文定位、参与者、已知条件、结果及后续依赖 |
| 因果记录 | 本次决策、条件检查、发生的行动、前后状态及失效事件 |
| 实验假设 | 来源类型、设定理由、不确定性及可调整参数 |

原著叙述本身未必明确说明充分条件或人物的全部目标。将“因果解释”写成规则时，需要标记为解释或假设。

## 行动库起点

候选行动包括：发起北伐、增援前线、保留后方兵力、召回部队、加强防备、议和、索取领土、结盟、策反及发动袭击。

规划器只能在已建模的行动空间内寻找后续路径。代码评估时要确认：表达一个行动需要多少人工工作，模型如何处理执行失败，以及找不到计划时如何停止并报告原因。

Sabre 的确定性规划与战争结果中的不确定性需要单独评估。第一版可以使用明确的离散结果规则，随后再决定是否增加概率模型。

## 两条对照路线

两条路线共享行动库、人物目标及结果规则。记录反事实干预及其必要配套状态变化，例如诸葛亮的位置、权限、调遣所需时间和益州的人手变化。

原著路线用于检查模型是否支持已知事件链，不能为了复现结局而把所有人物行为或事件结果固定下来。

反事实路线需要解释：

- 哪些原著事件仍满足条件？
- 哪些事件需要改变参与者、时机或结果？
- 哪些事件失效，具体失效条件是什么？
- 各方为了原有目标采取了哪些替代行动？
- 玩家下一次决策有哪些可行选项，各自代价是什么？

## 验收标准

1. 原著事件链在对应条件下可执行；条件被改变后，系统不会强制发生已失效的事件。
2. 每个重要新事件都有行动条件、角色动机、资源或时间代价及可核对的状态变化。
3. 人物不能同时处于互斥地点；兵力不能重复调动；资源不足、死亡或权限限制会阻止相应行动。
4. 角色只能依据已获得的信息做决策，情报的产生和传播有记录。
5. 玩家可以连续作出至少三次剧情级决策，每次都反馈到后续状态和可选行动。
6. 保存初始状态、模型版本、决策记录及使用随机性时的种子，以支持回放和分支对照。
7. 改动一组合理假设后重新检查结果，记录结论对哪些假设敏感。

## 首个里程碑交付物

- 三个参考仓库的代码评估：运行方式、数据模型、复用边界和接入成本。
- 一份带来源与假设标记的荆州局部模型。
- 可运行的基线与反事实对照，以及逐事件的状态变化和因果记录。
- 根据实际结果决定引擎和下一阶段范围。
