# 交接文档（给新对话）

新对话开头先读：本文、`CLAUDE.md`、`docs/roadmap.md`（机制表、世界线树、待办）、`README.md`。

## 项目一句话

AlterTale · 天命未定（原名异章）：以《三国演义》（毛宗岗本）为底本的反事实推演，玩家是刘备。故事质量第一；原著是默认轨迹，人物按演义行事。

## 和作者协作

- **一律用中文**交流（汇报、解释、提问）。
- **玩家对推演结果有疑问**：先从存档还原经过、给出解释；解释站得住就不改（"打不过不等于推演错了"）；只有凭空多兵、人物瞬移、未卜先知、违背演义这类不合理，才改规则或数据。见 `CLAUDE.md`。
- 作者不接受过长的局；看重谋士进言有用、不必主公开天眼。
- 作者常上传网页导出的存档（`/root/.claude/uploads/...json`），用 node 读 `game.chapters[i].state`、`game.past`（前几个时代）、`game.inherited`（承接开局的说明）来查。
- 每次跑完付费测试，报"本次多少钱、累计多少"（见下方账本）。

## 代码地图

- `web/engine.js`：全部推演逻辑（提示词、解析、复核、原著轨、评分、分支、过渡）。
- `web/index.html`：界面与调用流程（推演 → 复核 → 必要时重推 → 说书 → 外文修复）。开局页可导入存档（选文件，或粘贴文件内容：claude.ai 框架里选文件可能用不了）；承接开局的时代里有"回到上一时代终章，重新进入"（`E.undoTransition`），规则改了以后让作者重新过渡。
- `web/data/characters.js`：人物卡（按年份的称谓、性格、才能、目标）；`background.js`：背景大事。
- `web/data/eras/*.js`：各时代。`ruchuan` 入川、`hanzhong` 汉中、`jingzhou` 荆州、`yiling` 夷陵（四段原著线，可连打，夷陵以白帝托孤收尾）；`beifa` 北伐（手写分支，两个开局：`sample` 两路北伐、`yilu` 一路北伐）；`fujingzhou` 复荆州（模板分支，借荆州的地图人物，开局由过渡生成，只能从荆州分支进入）。
- `tools/check.js`：离线检查（零成本）；`tools/playtest.js`：自动对局测试；`tools/fixtures/`：各时代结局样本，用于测衔接；`tools/spend.json`：测试花费账本（每次模型调用后自动累加，已提交）。

## 每回的流水线

1. 驿程/分流（quick 档 `claude-haiku-5-5`），同时判"原著：是/否"。拆令提示词带兵马表：派兵的 from 取兵马实际所在（不看"成都兵"这类名号）；轻兵为轻装精兵数百至五千上下；`after` 表示接续前一项（如先回汉中领兵再出子午道），从前一项抵达之日、抵达之地起算；就地行动（from 与 to 相同）不加集结日。
2. 原著轨 `applyRail`：照原著下令就按原著节拍走；一旦偏离，本时代余下改为自由推演。
3. 推演（Sonnet）→ `checkSim` 复核（行军快过驿程、坐镇者未奉命离任、俘虏无故脱身、日期须写年月且不得倒退、一回不得远超日数上限）→ 有问题带着问题重推一次。日期只写季节也能解析（春初 = 正月上旬），章武、黄初年号折成建安。
4. 说书 → 逐段 `fixLatin` 去外文。
5. 时代结束：评分（原著 = 60 及格，六项各 ±15；低于 60 为败局"没能兴复汉室"；取长安为胜局"还于旧都"）→ 按 `ev.next` 分支进入下一时代。
6. 过渡：一路照原著打完 → 照原著快进（不调模型）；否则推演快进。过渡提示词带上历代人物的最后下落（`E.lastKnown`，跨全部 `g.past`）和各时代末的兵马；`checkTransition` 复核：换了地方要在其间大事里交代、刘备一方在世且在下一时代登场名单里的人不得消失、参考开局里刘备一方驻兵的要地不得一兵不剩。不合格带问题重推一次。坐镇（`posts`）由 `E.carryPosts` 延续：上一时代末仍在驻地的人，开局还在原处就照旧坐镇（按地名比对，中间时代地图上没有该地也不丢）；过渡中调走的视为改任；参考开局写明的坐镇者开局恰在其地也算。

## 测试分档（先便宜后贵）

1. `node tools/check.js [存档.json]`：配置、分支、重放全部对局的复核、衔接，免费。改完先跑它。
2. 从样本接着打：`node tools/playtest.js --era <前一时代> --starts canon --strategies prudent --from tools/fixtures/xxx.json --continue --turns 1 --label xxx`，约 $0.2–0.5（`--turns 0` 只测过渡）。
3. 整条原著回归（三段连打）约 $4–5，只在引擎或推演规则大改后跑。
4. `--strategies script --script "令一|令二"` 按指定命令打。
- 长测试用 `timeout`，日志写到 `playtest-out/log-*.txt`（不提交）。Haiku 做推演质量不够，已否决。
- 目前累计测试花费约 $46.5（10 月 7–9 日日志补记 + 之后自动累加）。

## 世界线（作者已定）

- 取长安（还于旧都）即胜；刘备下线即该线结束。原著夷陵线：夷陵后一章托孤，然后结束。有能赢的线，但不能条条都赢。
- 荆州结局分支（按序取第一条成立的）：江陵、公安俱在且孙刘未决裂 → 两路北伐；江陵在但公安失或孙刘决裂 → 东西两线（未写）；江陵失、关羽死 → 夷陵；江陵失、关羽活 → 复荆州。复荆州之后：荆州复全且未决裂 → 北伐，否则东西两线。
- 夷陵结局分支：刘备驾崩（交接清单"刘备：驾崩"）→ 白帝托孤，刘备线完结（`final` 分支，结局页显示 `text`）；复夺江陵且孙刘未决裂 → 两路北伐；复夺江陵而仍战 → 东西两线（未写）；章武二年以前、刘备在世（不伐吴或逼和）→ 一路北伐（分支带 `start: "yilu"`，过渡以该开局为参照）；否则 → 三分之局，完结。
- 夷陵第一个决断：伐吴 ／ 罢东征转图北伐 ／ 陈兵白帝逼和（东吴只肯让小筹码：关羽遗骸、糜芳士仁、范疆张达、秭归以西边界；荆州全境只能打）。
- 北伐的难度：洛阳中军（约五万）西援多少看东路压力（按兵不动→全数西援；围樊城、威胁宛→一半；破宛→基本断绝），孙权出合肥再分走一两万；一路北伐魏无东顾之忧，宛樊之兵也西调，最难。实测：东路克襄阳、围樊城时，曹丕西援二万五千，余屯宛许。
- 次要分支用模板节点（复荆州是试点，过渡和第一回测过两次，没完整打过）。
